# 拓扑优先生成试验

独立开发页面 `/generator-lab/`，不替换线上 `/generator-studio/`。自然语言由保管密钥的代理解析；模型推理和网格生成在浏览器运行。默认示例建议 12×12 米，三卧两卫，预算32。

## 下一阶段设计规范

用户新增的矩形满铺、300mm三维体素、楼梯贯通与简单形状要求，以及大模型—生成器反馈闭环，详见[协同生成流程与设计规则](DESIGN_RULES.md)。以下内容描述当前实现；留空与切角属于待替换的旧行为，尚未完成新规范验收。

## 本地预览

安装 Node.js 后，在网站仓库运行 `node scripts/serve-generator-lab.mjs`，打开 `http://127.0.0.1:8898/generator-lab/`。代理从环境变量 `PARSER_API_KEY` 或 `DASHSCOPE_API_KEY` 读取密钥，也支持用 `SPACEMODAL_ENV_FILE` 指向仓库外的环境文件。密钥不进入网页、Git或导出文件。没有密钥时，在连接设置切换“本地策略”。

## 流程

1. 代理生成房间实例、楼层、面积偏好及目标贴邻关系。用户可以先审阅拓扑，再确认生成。必需关系与偏好关系分别标记。
2. 校验11类功能、必需房间、数量、楼层、面积容量和目标图连通。明确取消的可选功能数量保留到后续对话；模型违反这些要求时返回错误。
3. 使用现有 HGNN_CVA 权重推理空间偏好，保持原模型推理接口。没有重新训练，也没有声称该模型已学习任意输入拓扑。
4. 在300mm水平网格放置房间核心、连接公共组织空间、扩展边界。房间保留独立实例，剩余网格保持空值。两层高度各3000mm；目前每层标签沿高度挤出，没有逐高度变化的分割。
5. 检查实例面连通、最低面积、上下楼梯投影一致和全部目标硬贴邻关系。只返回通过本试验检查的候选；失败会说明需调整条件。报告软关系缺失和实际面积偏差。
6. 展示两层平面、交互三维、目标与实际关系、模型原始预测。JSON包含未定义保留区域与两套拓扑；离线HTML包含平面、三维与A4拓扑。

## 边界

这是概念阶段原型，`project_accepted` 保持 `null`。贴邻检查不证明门、真实通行、疏散、采光或结构合理性；目标面积是偏好，当前评分不保证达到精确面积。空值区域不自动赋予庭院、挑空等用途。默认组织仍以楼梯和公共空间为中心，任意复杂拓扑可能搜索失败。紧凑边界和高房间数量不保证成功，不能将6–18米的输入范围理解为全部可生成范围。

代理新增 `/design`，原 `/parse` 保持兼容。上线实验版前需打包共享 `generator-lab/design.js` 模块、部署代理，并配置HTTPS `/design` 地址；本分支没有修改现有托管代理或生产网页。调用限制仍是单实例内存统计，不是持久的账户计费上限。

## 验证

- `node server/parser/scripts/test-proxy.mjs`：原解析接口兼容、来源检查、边界、调用限制。
- `node server/parser/scripts/test-design.mjs`：拓扑连通、取消功能和后续数量保持。
- 启动预览后运行 `node scripts/test-generator-lab.cjs`：真实模型三策略×三种子，以及页面、导出、恢复、响应布局。浏览器验证需安装Playwright；可用 `PLAN_PLAYWRIGHT_PATH` 和 `PLAN_CHROMIUM_PATH` 指定路径。

测试导出和截图写入被Git忽略的 `qa-artifacts/`。
