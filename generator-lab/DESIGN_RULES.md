# 协同生成流程与设计规则

本文是下一阶段生成器的目标规范。R1–R6来自用户明确要求；推荐的算法、评分和迭代次数是实现建议。本分支现已实现R1–R6独立校验与有界协同闭环，返回候选必须通过逐条检查；不得将本规范验收等同于完整建筑设计验收。

## 1. 优化方向

采用“大模型提出方案—生成器求解—独立校验—反馈调整”的闭环。大模型负责房间计划、目标关系、楼层组织和面积偏好；生成器负责模数化几何求解；校验器负责判断规则是否满足。现有训练模型可以提供位置偏好，不能覆盖用户要求或硬规则。

生成失败时，先在不改变已确认需求和目标关系的前提下尝试局部修复、位置调整或换种子；仍失败再将结构化原因交给大模型。这样可以区分一次几何搜索失败与真正的需求冲突。

大模型不能通过降低规则、删掉用户要求的房间、擅自扩大边界来“修好”结果。确需改变用户硬要求时，展示具体变更及原因，等待用户确认；未经确认不能生成并宣称满足原需求。

## 2. 硬规则 R1–R6

| 编号 | 用户要求及操作定义 | 验收依据 |
| --- | --- | --- |
| R1 | 矩形体量满铺。边界内部每个体素都有11类功能之一及唯一独立空间归属；实例存在且实例功能与体素功能一致。禁止空值、重叠、孤立ID和越界占用。 | 有效体素覆盖率100%；空值、非法标签、归属冲突和越界数量均为0。不能仅靠随意填成走道或客厅实现满铺，仍须通过其余几何和拓扑要求。 |
| R2 | 所有尺寸与边界符合300mm模数。外边界、空间边界、位置坐标、楼层界面及构成形状的矩形端点均落在同一整数网格。 | 使用整数网格求解；导出毫米坐标均为300的整数倍。禁止先连续计算后静默取整改变用户尺寸。 |
| R3 | 楼梯采用一致的独立实例归属，按共享面连通；上下层平面投影对齐，跨越3000mm楼层界面并贯通两层。角接触、棱接触或上下错位不算连通。 | 上下层楼梯掩码一致；楼梯实例的三维六邻域连通分量为1，并存在跨层界面的上下共享面。这里只验功能体块贯通，不等同于已经设计踏步和平台。 |
| R4 | 固定两层，每层3000mm，总高6000mm。 | 一层范围z∈[0,3000)，二层范围z∈[3000,6000)；总计20个体素高度层，每层楼10个。 |
| R5 | 基本体素为300×300×300mm。 | 三轴体素间距均为300mm，使用统一原点；边界为Nx×Ny×20个体素。只保存两张平面时，必须明确沿高度展开的映射，导出和验收不得混淆平面格与体素。 |
| R6 | 每个独立空间按三维六方向共享面连通，无游离碎片；每个实例为矩形或矩形拼接的L型，走道可放宽至工字型，体量尽可能简单。 | 对每个实例检查六邻域连通分量为1；采用下面的形状白名单精确比对，禁止用外包矩形替代实际形状检查。白名单之外的T型、U型、孔洞和锯齿形不通过；在合格形状中优先简单形状。 |

合法功能集合固定为：玄关、客厅、餐厅、厨房、卧室、卫生间、过道、楼梯间、家政空间、阳台、多功能室。功能类别与独立实例ID分开存储：两间卧室属于同类功能，但归属不同实例。

### 形状定义与三维表达

为使R6可计算，本阶段推荐将“矩形／L型／工字型”定义为楼层平面轮廓；同一楼层内沿高度保持一致，形成三维直棱柱。此定义承接当前固定层高的表达方式，尚不引入逐高度变化的自由形态。

- 普通实例：单个轴对齐矩形，或两个轴对齐矩形拼接得到的标准L型。L型应无孔洞、无碎片且仅有一个内凹转角；矩形拼接后恰好覆盖该实例，不能夹带其他实例或空格。
- 走道实例：允许上述矩形、L型，以及一条中间连接带与两端平行横带构成的标准工字型。允许旋转；不将任意三个矩形的并集视作工字型。
- 楼梯：上下层采用相同的合格轮廓，并作为贯通实例检查三维连通。
- 形状简单性在白名单内比较：优先矩形，其次L型，走道最后考虑工字型。可附加比较内凹角数量、周长和狭窄部分，但具体最小宽度与权重须单独定义，不能冒充R1–R6已规定的数值。

矩形体量满铺意味着取消当前的对角切角、预留空白和未分配区域。大模型提出的目标面积需要结合整层总面积重新协调；面积偏好不可能一边固定总和不足，一边要求全部空间严格达到原目标并满铺。

## 3. 推荐的生成与反馈闭环

1. 需求规范化：区分用户锁定项、可调整项及系统规则，保留来源。锁定项包括明确尺寸、房间数量、楼层安排和必需关系等；R1–R6始终为硬规则。未明确要求的目标面积可以作为软偏好。
2. 大模型给出结构化计划：列出独立实例、功能、楼层、面积目标或允许区间、目标关系及可调整项。用户明确取消的可选功能继续保持数量0。
3. 生成前可行性检查：核对模数、每层最低面积容量、实例数量及关系图。容量已经明确冲突时，不先进行大量随机搜索。仅依据最低面积不能保证布局可实现。
4. 几何求解：对整个矩形楼层进行完整分区，同时保证实例形状白名单和楼梯贯通。建议从“放房间后零散填空”改为“完整分区＋矩形片组合成实例”；不再围绕唯一公共中心机械连接全部房间。目标图应进入分区和局部调整过程，而非仅在最后检查。
5. 独立验收：输出R1–R6逐条结果，以及必需关系、最低面积等其他已声明约束的结果。校验器从最终体素归属重新计算，不信任生成器自行声称通过。
6. 局部修复：先移动共享边界、交换相邻矩形片、重组L型或公共空间。在保持全部硬要求的前提下修复；若修复引入新违规则回退。
7. 结构化反馈：仍失败时，把具体违规、相关实例、目标与实际值、已尝试的调整送给大模型。大模型仅修改允许调整的面积偏好、组织策略或非锁定关系。
8. 再生成：每轮检查计划变更，确保锁定项未变；保留上一轮有效结果和全过程记录。推荐最多3轮大模型修订，并配总时间与调用预算；本分支已采用此边界，生产网站尚未部署此实验功能。无有效候选则停止并说明原因，不用违规方案替代。
9. 候选排序：先排除硬规则违规，再比较面积偏差、偏好关系、形状简单性和组织效果。不能用综合评分抵消硬规则失败。

### 反馈内容

每轮至少记录：轮次、策略ID、随机种子、搜索预算、规则版本、失败类型、受影响实例、目标值、实际值、证据、局部修复结果、允许修改项及禁止修改项。

例如：“R6失败：bedroom-2产生两个内凹角，不符合矩形/L型；R1失败：二层存在48个未分配体素。用户锁定12×12米、三卧两卫、两层高度；可调整二层房间面积偏好及公共联系组织。已尝试边界移动，未成功。”

反馈必须区分：确定的规则冲突、某轮搜索未找到解、代理不可用和计算超时。一次搜索失败不能表述为需求不可能实现。建议改动必须依据报告，不让大模型猜测几何失败原因。

### 用户看到的流程

显示“提出策略 → 生成尝试 → 校验 → 调整策略 → 再次生成”的简短进度；允许展开每轮失败原因和变更。只有涉及已锁定需求变更时要求确认，普通位置搜索及允许范围内调整可自动进行。始终支持停止，保留历史合格方案。

## 4. 当前实现状态与限制

- 在确认前规范化模型数量字段，并补齐缺失公共联系；用户未指定贴邻时，按公共联系规则整理推断关系，其他推断联系保留为偏好，变化明确显示供审阅。用户明确的贴邻不被放宽，确认后的自动修订不能增删必需关系。
- 已取消切角和空值；完整矩形分区生成器返回100%合法归属。
- R1–R6由rules.js独立校验，按20层展开检查六方向共享面连通；形状检查支持矩形/L型和走道工字型。
- 当前生成器主要生成矩形和L型，采用可旋转的公共带分区、房间关系分组和片交换局部修复。工字型已可校验，但生成器尚未主动搜索工字型走道；任意复杂拓扑仍可能搜索失败。
- 在线模式在搜索失败后提交结构化容量/关系报告，最多3次模型修订，最多4轮几何求解，总时限180秒。取消会中止当前工作线程或代理请求。
- 自动修订保守冻结所有已确认房间实例、功能、楼层、数量和必需关系；仅调整组织模式、面积偏好和软关系。若确需改楼层或必需关系，停止并由用户重新确认需求，而不静默放宽。
- 当前保存为两层归属网格＋明确的20层挤出映射；校验时实际展开三维体素，不引入层内随高度变化的形态。
- 成功和失败历史均可查看；新一轮失败不会覆盖之前的有效结果，旧版不合规则的缓存不会自动恢复为合格结果。
- 真实模型三策略×三种子、规则反例、闭环保护、网页导出及真实模型修订例程均已有测试；这不证明全部尺寸和需求均能求解。

现有 position priors 只是辅助，不能证明模型已学习任意拓扑；不需要先重新训练才能建立上述闭环。后续是否重训，应依据闭环积累的失败类型与实际收益判断。

## 5. 推荐实施顺序与验收材料

优先实现统一体素归属、R1–R6独立校验和结构化失败报告；其次实现满铺及形状受限的几何求解、局部修复；最后接入大模型迭代与进度展示。不要先让大模型反复调用当前不符合满铺与形状规则的生成器。

验收应覆盖：矩形、L型、工字型合格样例，以及空值、非法标签、重叠归属、角接触、碎片、上下楼梯错位、孔洞、T型/U型和非300mm边界等失败样例。再用多种边界、房间数量和随机种子检查生成结果。

每个候选同时保留最终归属数据、两层平面、交互三维、目标/实际拓扑、R1–R6逐条报告，以及协同迭代记录。通过本规范仍不等于门、真实通行、疏散、采光或结构已完成设计；未覆盖的建筑要求必须另列校验，不能宣称完整建筑设计验收通过。
